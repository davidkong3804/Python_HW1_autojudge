# Autojudge：程式作業自動批改平台（助教工具）

**批改網頁：<https://davidkong3804.github.io/Python_HW1_autojudge/>**

這是給**助教批改作業用**的工具，不是給同學練習的 Online Judge。
一個網頁批所有作業：上方切換 **HW1 / HW2 / …**，每份作業有自己的測資、參考解答、配分與批改進度。

學生的程式在**你自己的瀏覽器裡**執行（Pyodide = WebAssembly 版 CPython），
不會上傳到任何伺服器，也不用架機器。

> ⚠️ 這個 repo 是公開的，`hw/*/tests/`、`data/` 裡就是完整測資與標準答案，網址流出去同學就看得到。
> 不想讓同學在截止前看到，就先不要把網址貼出去，助教之間用本機開（見下面「本機開最快」）。

| 作業 | 題目 | 配分 | 繳交格式 |
|---|---|---|---|
| HW1 | BMI、計算機、質數、數字和、密碼強度、一元二次方程式 | Q1~Q4 各 15、Q5~Q6 各 20；每題 5 組測資 | `學號_HW1/q1.py ~ q6.py` |
| HW2 | 反轉單字、質數產生器、去除重複、共同元素、二進位轉十進位、日期計算（[定稿](hw/hw2/handout.pdf)） | Q1~Q4 各 20（a、b 子題各 10）、Q5~Q6 各 10；每個子題 5 組測資 | `學號_HW2/q1a.py、q1b.py … q4b.py、q5.py、q6.py` |

新增 HW3 看 [`hw/README.md`](hw/README.md)：放一個資料夾、跑兩行指令，網頁上就會多一個 HW3，不用改網頁程式。

## 一、批改流程

1. **開網頁，上方選作業**（HW1 / HW2…）。右上角「Python 尚未載入」是正常的，放檔案時才會準備。
2. **把 zip 拖進去** —— 幾十份一起拖沒問題。COOL 整包下載那種「zip 裡面還有 zip」也吃得下；
   散裝 `.py`、整個資料夾一樣可以。學號和題號會自動從路徑抓出來。
   放進來的檔案路徑寫的是 HW1、畫面卻停在 HW2 時，會跳提醒並可以一鍵搬過去。
3. **確認對應關係** → 一位學生一列，顯示「10 題齊全 / 缺 Q4a / 待指定」。
   點一下展開，題號用下拉選單改，學號改一次就套用到整份作業。勾「只看需要處理的」把對好的收起來。
4. **按「開始批改」** → 成績表出來。可以隨時按「取消」，已經批完的人會保留。
5. **看成績、處理例外**：點任何一格分數，右邊會打開那位學生的細節——
   程式碼、每一筆測資的輸入 / 應該輸出 / 實際輸出、寫法要求提示，以及**手動加減分**（要寫原因）。
   按 `J` / `K` 換下一位 / 上一位學生，`←` / `→` 換題目，不用一直捲回表格。
6. **匯出**：「匯出成績 CSV」登成績，「匯出回饋」得到每位學生一段文字（錯在哪幾筆、手動調整原因），可以直接貼 COOL 評語，
   「明細 JSON」留逐筆紀錄備查。

批改進行中檔案清單會鎖住（不能加檔、改題號、切換作業），批完或按「取消」就解開。
同一個網頁請只開一個分頁，開兩個會跳警告（兩邊的自動儲存會互相覆蓋）。

**進度會自動存在這台電腦的瀏覽器裡**（右上角「已自動儲存」）：重新整理、關掉分頁、切換作業都不會不見，
每份作業各自保留。要重來按步驟 2 的「清空這份作業」。

第一次用建議先按一下 **「先驗證參考解答」**，應該剛好 100 分 —— 確認你的瀏覽器跟測資是一致的
（結果只顯示在按鈕下方，不會蓋掉成績表）。按 **「載入示範」** 可以看故意寫錯的程式各被扣到幾分。

### 成績表上的標記

| 標記 | 意思 |
|---|---|
| ⚑ | 寫法要求提示（例如 HW2 Q1b 規定只能用切片卻用了迴圈）。**只提示、不自動扣分**，點開看程式碼後自己決定 |
| ✎ | 這一格有手動加減分，滑鼠停上去看原因 |
| ⚠ | 同一位學生同一題交了不只一份，全部都跑，取最高分 |
| 需重批 | 批改之後這位學生的檔案有變動（改了題號、學號、加了檔案），按上方黃色提示的「只重批這幾位」 |
| 未繳交 / 不在名單 | 有匯入修課名單才會出現，見下面 |

表格可以點欄位標題排序、搜尋學號姓名、篩選「沒滿分 / 有 ⚑ / 有手動調整 / 未繳交…」。
表尾有每題平均，平均特別低的那一題會標紅——通常值得點開幾位看看是不是測資或題意的問題。

批改後改了測資、配分或比對方式，表上會提醒「分數是舊設定的結果」，這時只能全部重新批改
（不讓同一張成績表混用兩套標準）。匯出時如果還有沒重批的，會先問你一次。

### 修課名單（選用）

步驟 1 下方「匯入名單 CSV」：COOL 或 Excel 匯出的名單都可以，只要有一欄是學號，旁邊的姓名欄會一起讀進來。
匯入後：

* 沒交的同學也會列在成績表上（0 分、標「未繳交」），匯出的 CSV 可以直接整份貼回成績簿
* 不在名單上的學號會標出來——多半是學號辨識錯了，展開改學號即可
* 名單所有作業共用，只要匯入一次

### 第一次開會等一下

第一次要下載 Python 執行環境（傳輸約 5.5 MB、解壓後 11.7 MB），網路慢的話 30～60 秒，
右上角有百分比。下載完存在瀏覽器快取，之後重開只要**兩三秒**。

### 本機開最快（要批很多份建議這樣）

把 repo clone 下來，雙擊 `start_local.command`（macOS），
或在資料夾裡執行 `python3 -m http.server 8765` 再開 <http://localhost:8765/>。
Python 環境直接從硬碟讀，**約三秒、完全不用網路**，測資也不會外流。
網址後面加 `#hw2` 可以直接打開 HW2。

## 二、判定規則（同學會來問的就是這些）

| 狀態 | 意思 |
|---|---|
| 正確 | 輸出與正解相符 |
| 答案錯誤 | 程式跑完了但輸出不對 |
| 格式不符（算錯） | 答案印對了，但多印了說明文字或提示字（`BMI = 55.56`）。**依老師規定算錯**，只是另外標出來方便助教查 |
| 輸出正確但程式出錯 | 答案印對了，程式之後才爆掉（多半是結尾多一個 `input()`）→ **仍然給分** |
| 執行錯誤 | 語法錯誤 / 例外，會顯示乾淨的 Traceback |
| 執行逾時 | 預設 8 秒。無窮迴圈，或程式還在等下一個 `input()` |

### 輸入：一行就是一次 `input()`（老師的規定）

* 測資是 `10 10 10` 一行 → 就是**一次** `input()`，自己 `split()` 拆開
* 測資是三行 `10` / `10` / `10` → 就要**三次** `input()`（例如 HW2 Q4 兩個 list 分兩行）

把一行拆成 `h=input()`、`w=input()` 兩次讀的同學，第二次讀不到東西會 `EOFError`，**判錯**。

> 步驟 3「進階設定」裡可以改成接受，打開後會把那一行拆成逐行輸入重跑一次。除非老師改口，否則不要打開。

### 寫法要求（HW2 起）

HW2 每題規定寫法（a 用迴圈、b 只用切片；用 for / while；要定義函式；用 set；用 datetime），
這種要求測資測不出來。平台會用 Python `ast` 靜態分析（只分析、不執行），不符合的標 ⚑ 提示。
**不會自動扣分**：靜態分析會有誤判（例如用了遞迴而不是迴圈），最後由助教看程式碼決定，
需要扣分就在細節裡「手動調整」並寫原因，原因會寫進成績 CSV 和回饋。

### 這些寫法不扣分

| 同學的寫法 | 怎麼處理 |
|---|---|
| `input("請輸入身高：")` 有提示字 | 提示字不算輸出 |
| `sys.stdin.read()` 一次吃完 / `for line in sys.stdin` | 本來就吃得下 |
| 印完答案後多一個 `input("按 Enter 結束")` | 輸出正確就給分 |
| 檔案存成 Big5 / UTF-16 / 有 BOM / CRLF | 自動辨識編碼，不會變成語法錯誤 |
| `sys.exit()`、用到 `__file__`、把 `sys.stdout` 關掉 | 都不影響 |

### 老師的規定：格式不對、交 .ipynb 一律算錯

> 「答案正確但未照範例輸出格式（如打成 /、多打空格、多打 bmi =）」「ipynb 手動轉檔」——**直接給錯，不用幫同學修**。

所以批改程式預設：

* 輸出要跟正確答案**一模一樣**（只忽略行尾看不見的空白與結尾空行）
* 多印了說明文字（`BMI = 55.56`）、提示字（「請輸入身高：」）的，標成「**格式不符（算錯）**」——
  跟一般答錯一樣 0 分，只是另外標出來，成績表「備註」欄看得到，也能篩選「格式不符」
* 交 `.ipynb` 的，標成「**交 .ipynb（依規定算錯）**」，不轉檔、不執行

### 助教改判（保留破例的權利）

點任何一格分數打開細節，每一筆測資右邊都有一個按鈕：

* 判錯的那筆按「**改判對**」、判對的按「**改判錯**」，分數馬上重算，不用重批，會自動存檔
* 改判過的標「助教改判」，按「取消改判」回到原本的判定
* 成績表備註欄顯示「改判 N 筆」，CSV 的「狀態」欄與回饋文字都會寫出來

真的要讓某位同學的 `.ipynb` 破例批改：步驟 2 展開他、在那個檔案按「拆成程式碼」，拆完指定題號後重批。

### 進階設定（步驟 3，老師沒另外交代就不用動）

| 問題 | 選項 | 預設 |
|---|---|---|
| 空白或大小寫不一樣（`weak` 對 `Weak`；行尾空白一律不算錯） | 算錯 / 空白不算錯 / 空白、大小寫都不算錯 | **算錯** |
| 答案印對了，但程式最後才出錯（多寫 `input('按 Enter 結束')`） | 算對 / 算錯 | **算對** |
| 一行的輸入拆成好幾次 `input()` | 算錯（老師規定）/ 接受 | **算錯** |
| 每筆測資最多跑幾秒 | 秒數 | 8 秒 |

改過的話，「開始批改」下面會多一行黃字提醒。

「格式不符」的判定刻意保守，只認這幾種：答案前面是 `標籤:`、`標籤 =`、`… is`、`…是`、`…為`（標籤裡不能有數字），
後面只有標點，多印的整行只能是提示字（以 `:` `：` `?` 結尾）。認不出來的就是一般的「答案錯誤」——反正都算錯，
這個標記只是讓助教好找。

## 三、遇到狀況怎麼辦

| 狀況 | 處理 |
|---|---|
| 某格分數看起來怪 | 點那一格，看程式碼和逐筆「應該輸出 vs 實際輸出」，通常一眼就知道是格式還是邏輯問題 |
| 檔名是 `3 (1).py`、`ex3_ver2.py` 這種有兩個數字的 | 不會猜，會標「待指定」：以前會默默掛到錯的題目。按「自動配對」或手動選 |
| 學號認錯 / 題號沒認出來 | 在步驟 2 展開那位學生直接改；學號改一次就套用到他整份作業。認不出題號的可以按「自動配對題號」，它會拿每題前兩筆測資試跑來判斷 |
| HW2 只交 `q1.py` 沒寫 a / b | 會標「待指定」。a、b 的輸入輸出一樣，自動配對**分不出來**，只會先放到這位學生還缺的那一個並標「子題請確認」，請看程式碼判斷 |
| 改完題號 / 學號 | 成績表上方會出現「只重批這幾位」，不用全部重跑 |
| 同一位同學同一題有多份檔案 | 全部都會跑，取最高分並標 ⚠ |
| 同學反應測資不對 | 先看 `hw/<作業>/tests/README.md`，每一組都寫了「這組在測什麼」。真的有錯就改 `hw/<作業>/spec.py` 重新產生並重跑驗證 |
| 同學交 Colab 的 `.ipynb` | 依老師規定算錯、不轉檔。要破例：步驟 2 在那個檔案按「拆成程式碼」 |
| 想確認環境正常 | 按「先驗證參考解答」，應該 100 分 |
| 不想開瀏覽器 | 用命令列版，見第五節 |

### 「為什麼我 0 分」— 回同學時可以直接用的清單

1. 檔名不是公告的題號（HW1 `q1.py`、HW2 `q1a.py`），或沒有放在 `學號_HWn/` 資料夾裡
2. 把一行輸入拆成好幾次 `input()`（題目是一行，就只能讀一次）
3. 輸出格式不對：少補小數位（`25` 要寫成 `25.00`）、用逗號而不是空白分隔（或反過來）、大小寫不符（`weak` ≠ `Weak`）
4. 語法錯誤 —— 交出去前至少自己跑過一次
5. 用了 `numpy` 之類的第三方套件（批改環境只有標準函式庫）
6. 無窮迴圈，或程式還在等下一個輸入

「匯出回饋」產生的文字已經列出每一題錯在哪幾筆，通常直接貼給同學就夠了。

## 四、調整測資與配分（網頁最下面的「測資與配分設定」）

批改頁面最下面有一區可以自己改測資與配分，不用改程式、不用重新部署。**每份作業各自一套設定。**

**關掉某些測資。** 取消勾選就不列入這次批改。配分模型是**題目總分固定，啟用中的測資平分**——
關掉一組不會讓總分變少，而是讓剩下的每一組變重。例如 HW1 Q2 關掉 2 組，剩下 3 組就從每組 3 分變成每組 5 分，
Q2 仍然是 15 分，總分仍然是 100。

**加自己的測資。** 只要填 input，**正確輸出由頁面實際執行參考解答產生**，不用自己打答案。
參考解答跑這筆輸入會出錯（例如格式不合題目規定），就不會讓你加進去，並且會把錯誤訊息顯示出來。

**改每題配分。** 直接改數字。總分不等於 100 時會紅字警告，某一題被關到一組測資都不剩時也會警告。

幾個要知道的：

- 設定存在**你這台電腦的瀏覽器**裡，不會跟著網址跑。換電腦或換助教請用「匯出設定 JSON」／「匯入設定 JSON」。
  匯出的檔案會記得是哪一份作業的，匯入到別份作業會先問你。
- 成績表、匯出的 CSV、匯出的 JSON **都會附上這次用了哪些設定**。設定可以無聲地改變成績，所以報表上一定要留下紀錄。
- 批改跑到一半改設定不會影響正在跑的那一輪——每次批改開始時會把設定固定下來。
- 匯出的 JSON 可以直接交給命令列版，讓兩邊用同一套設定：

```bash
python3 tools/grade_cli.py 繳交資料夾/ --hw hw2 --config hw2_批改設定.json
```

## 五、命令列批改（離線備援）

```bash
python3 tools/grade_cli.py 繳交資料夾/                    # 作業從檔名的 _HWn 自動判斷
python3 tools/grade_cli.py 繳交資料夾/ --hw hw2           # 指定作業
python3 tools/grade_cli.py *.zip -o 成績.csv --detail 明細.json
python3 tools/grade_cli.py 繳交資料夾/ --config 設定.json  # 套用網頁上調好的測資與配分
```

判定邏輯與網頁版**完全一致**：同一份 `data/<作業>.json`、同樣的輸出正規化、同一套 `input()` 攔截方式、
同一段寫法分析程式（直接從 `assets/worker.js` 讀出來用），
而且用 `python -I -S` 執行（不載入 site-packages），避免「網頁 0 分、助教電腦裝了 numpy 就滿分」。

常用選項：`--timeout 8`、`--strict-output`、`--lenient-input`、`--detail 明細.json`。
（`--format-credit` 預設 0，依老師規定不要改。）
設定檔是別份作業的（例如 HW1 的設定拿來批 HW2）會直接擋下來。
命令列版沒有改判、手動調整與名單；交 `.ipynb` 的會列出來、不批改。這些請用網頁版。

## 六、測資怎麼出、怎麼驗的（要接手維護再看）

每份作業的題目、測資、驗算都在 `hw/<作業>/spec.py`，格式與新增作業的步驟見 [`hw/README.md`](hw/README.md)。

測資慣例（HW1 定版，之後的作業沿用）：每題（子題）5 組手工挑選的特殊測資，預期輸出一律**實際執行參考解答**產生，
不採用作業 PDF 上的範例（學生手上已經有，沒有鑑別度），也不放隨機測資——只有 5 組額度，每一組都要換到一個明確的鑑別點。
每一組在測什麼，看 [`hw/hw1/tests/README.md`](hw/hw1/tests/README.md)、[`hw/hw2/tests/README.md`](hw/hw2/tests/README.md)。

```bash
python3 tools/generate_tests.py  # 產生測資（全部作業；--hw hw2 只產一份）
python3 tools/verify_tests.py    # 測資正確性（五道防線；--hw hw2 只驗一份）
python3 tools/test_detect.py     # 學號 / 題號（含子題）辨識、寫法分析
python3 tools/test_config.py     # 測資與配分設定的算法
python3 tools/stress_test.py     # 批改程式扛不扛得住奇怪的學生程式
```

`verify_tests.py` 的五道防線：參考解答全過 → 另一份刻意用不同寫法的獨立實作也全過 →
用 `spec.py` 的 `INDEPENDENT`（不重用任何一份解答的程式碼）重算一次（抓「兩份解答犯同一個錯」）→
`mutants/` 裡每一支故意寫錯一兩行的程式都必須至少被一組測資抓到 → 每題 300 筆隨機輸入兩份實作逐字對拍。

`stress_test.py` 灌 21 支惡夢程式：無窮迴圈、無窮 `print`、吃記憶體、無窮遞迴、空檔案、語法錯誤、
BOM / Big5 / UTF-16，以及**竄改 `builtins` 或 `math` 的程式**（每跑完一筆就還原全域狀態）。

`test_detect.py` 固定一批路徑（含 HW2 的 `q1a`、`Q1(b)`、`4b`、只寫 `q1` 要留空…），檢查學號與題號都判對，
同時用 node 把 `assets/app.js` 的辨識段落抓出來跑一遍，確認網頁版與 CLI 版對同一條路徑給出相同答案。
`test_config.py` 同樣把 `app.js` 的設定段落抓出來跟 `grade_cli.py` 對拍。

全部接在 `.github/workflows/verify.yml`，每次 push 自動跑。

**還是請三到四位助教各自寫一次作業、跑過測資**：自動驗證擋得住實作 bug，
擋不住「題目本身有兩種合理解讀」。

改完務必依序跑：

```bash
python3 tools/generate_tests.py && python3 tools/verify_tests.py \
  && python3 tools/test_detect.py && python3 tools/test_config.py \
  && python3 tools/stress_test.py
```

`git push` 之後 GitHub Pages 會自動重新建置（一兩分鐘），網址不變。
改了 `assets/` 或 `data/` 之後，把 `index.html` 與 `assets/app.js` 裡的 `?v=` 版本號加一，
助教的瀏覽器才不會拿到舊的快取。

## 七、檔案結構

```
index.html                批改網頁（GitHub Pages 入口）

tools/grade_cli.py        命令列批改（判定與網頁版一致）
vendor/pyodide/           Pyodide 執行環境（約 12 MB，讓網頁離線可用）
```

# HW1 自動批改（助教工具）

**批改網頁：<https://davidkong3804.github.io/Python_HW1_autojudge/>**

這是給**助教批改 HW1 用**的工具，不是給同學練習的 Online Judge。
裡面有六題的測資、參考解答、驗證工具，以及一個直接跑在瀏覽器裡的批改網頁。

學生的程式在**你自己的瀏覽器裡**執行（Pyodide = WebAssembly 版 CPython），
不會上傳到任何伺服器，也不用架機器。

> ⚠️ 這個 repo 是公開的，`tests/`、`data/` 裡就是完整測資與標準答案，網址流出去同學就看得到。
> 不想讓同學在截止前看到，就先不要把網址貼出去，助教之間用本機開（見下面「本機開最快」）。

```
配分：Q1~Q4 各 15 分、Q5~Q6 各 20 分，共 100 分
測資：每題 5 組 → Q1~Q4 每組 3 分、Q5~Q6 每組 4 分（同作業公告）
繳交格式：學號_HW1.zip  →  學號_HW1/q1.py ~ q6.py
```

## 一、三步驟批改

1. **開網頁** → 上面那個網址。右上角顯示「Python 尚未載入」是正常的，放檔案時才會準備。
2. **把 zip 拖進去** —— 幾十份一起拖沒問題。COOL 整包下載那種「zip 裡面還有 zip」也吃得下；
   散裝 `.py`、整個資料夾一樣可以。學號和題號會自動從路徑抓出來，認錯可以用下拉選單改。
3. **按「開始批改」** → 成績表出來。點任何一格可以看那題 10 筆測資的逐筆輸入 / 應該輸出 / 實際輸出。
   最後按「匯出 CSV」登成績，「匯出 JSON」留逐筆明細備查。

第一次用建議先按一下 **「先驗證參考解答」**，應該剛好 100 分 —— 確認你的瀏覽器跟測資是一致的。
按 **「載入示範」** 可以看 24 支故意寫錯的程式各被扣到幾分。

## 二、判定規則（同學會來問的就是這些）

| 狀態 | 意思 |
|---|---|
| 正確 | 輸出與正解相符 |
| 答案錯誤 | 程式跑完了但輸出不對 |
| 輸出正確但程式出錯 | 答案印對了，程式之後才爆掉（多半是結尾多一個 `input()`）→ **仍然給分** |
| 執行錯誤 | 語法錯誤 / 例外，會顯示乾淨的 Traceback |
| 執行逾時 | 預設 8 秒。無窮迴圈，或程式還在等下一個 `input()` |

### 輸入：一行就是一次 `input()`（老師的規定）

測資長什麼樣，同學就要怎麼讀：

* 測資是 `10 10 10` 一行 → 就是**一次** `input()`，自己 `split()` 拆開
* 測資是三行 `10` / `10` / `10` → 就要**三次** `input()`

HW1 六題的測資**每題都只有一行**，所以正解就是一次 `input()`。
把一行拆成 `h=input()`、`w=input()` 兩次讀的同學，第二次讀不到東西會 `EOFError`，**判錯**。

> 「開始批改」那排有一個預設**關閉**的非標準選項「（非標準）相容『一行拆成多次 input()』」，
> 打開後會把那一行拆成逐行輸入重跑一次。除非老師改口，否則不要打開。

### 這些寫法不扣分

| 同學的寫法 | 怎麼處理 |
|---|---|
| `input("請輸入身高：")` 有提示字 | 提示字不算輸出 |
| `sys.stdin.read()` 一次吃完 / `for line in sys.stdin` | 本來就吃得下 |
| 印完答案後多一個 `input("按 Enter 結束")` | 輸出正確就給分 |
| 檔案存成 Big5 / UTF-16 / 有 BOM / CRLF | 自動辨識編碼，不會變成語法錯誤 |
| `sys.exit()`、用到 `__file__`、把 `sys.stdout` 關掉 | 都不影響 |

### 可以調的選項（在「開始批改」那一排）

| 選項 | 預設 | 說明 |
|---|---|---|
| 單筆測資逾時 | 8 秒 | 同學寫得很慢（例如質數迴圈跑到 n）時可以調大 |
| 比對方式 | 嚴格 | 只忽略行尾空白與結尾空行；另有「忽略每行前後空白」「忽略所有空白與大小寫」 |
| 每題錯一筆就跳過剩下的 | 關 | 只想看誰過誰沒過時打開，會快很多 |
| 只要輸出正確就給分 | **開** | 印完答案才出錯的不扣分 |
| （非標準）相容一行拆多次 input() | **關** | 見上面 |

成績表下面會寫「這次有幾筆是靠寬鬆規則過的」，方便抽查。

## 三、遇到狀況怎麼辦

| 狀況 | 處理 |
|---|---|
| 某格分數看起來怪 | 點那一格，逐筆看「應該輸出 vs 實際輸出」，通常一眼就知道是格式還是邏輯問題 |
| 學號認錯 / 題號沒認出來 | 表格裡直接改。認不出題號的可以按「自動配對」，它會拿每題前兩筆測資試跑來判斷 |
| 同一位同學同一題有多份檔案 | 全部都會跑，取最高分並標 ⚠ |
| 同學反應測資不對 | 先看 [`tests/README.md`](tests/README.md)，每一組都寫了「這組在測什麼」。真的有錯就改 `tools/generate_tests.py` 重新產生並重跑驗證 |
| 同學交 Colab 的 `.ipynb` | 會自動拆成一格一格的 code cell（`!pip`、`%magic` 會略過），再用「自動配對」判斷哪格是哪題 |
| 想確認環境正常 | 按「先驗證參考解答」，應該 100 分 |
| 不想開瀏覽器 | 用命令列版，見下一節 |

### 「為什麼我 0 分」— 回同學時可以直接用的清單

1. 檔名不是 `q1.py`~`q6.py`，或沒有放在 `學號_HW1/` 資料夾裡
2. 把一行輸入拆成好幾次 `input()`（題目是一行，就只能讀一次）
3. 輸出格式不對：少補小數位（`25` 要寫成 `25.00`）、用逗號而不是空白分隔、大小寫不符（`weak` ≠ `Weak`）
4. 語法錯誤 —— 交出去前至少自己跑過一次
5. 用了 `numpy` 之類的第三方套件（批改環境只有標準函式庫）
6. 無窮迴圈，或程式還在等下一個輸入

## 四、命令列批改（離線備援）

```bash
python3 tools/grade_cli.py 繳交資料夾/                    # 裡面放一堆 學號_HW1.zip
python3 tools/grade_cli.py *.zip -o 成績.csv --detail 明細.json
```

判定邏輯與網頁版**完全一致**：同一份 `data/tests.json`、同樣的輸出正規化、同一套 `input()` 攔截方式，
而且用 `python -I -S` 執行（不載入 site-packages），避免「網頁 0 分、助教電腦裝了 numpy 就滿分」。

常用選項：`--timeout 8`、`--strict-output`、`--lenient-input`、`--detail 明細.json`。

## 五、測資怎麼出、怎麼驗的（要接手維護再看）

`tools/generate_tests.py`：每題 5 組手工挑選的特殊測資，預期輸出一律**實際執行參考解答**產生，不手寫答案。
測資不採用作業 PDF 上的範例（學生手上已經有，沒有鑑別度），也不放隨機測資——
只有 5 組額度，每一組都要換到一個明確的鑑別點。
挑選的門檻是 `tools/verify_tests.py` 的第四道防線：每題 4 支漏洞程式都必須至少被一組測資抓到。

每題刻意放的坑（完整表格見 [`tests/README.md`](tests/README.md)）：

| 題 | 坑 |
|---|---|
| Q1 | BMI 剛好整數（要補成 `25.00`）、身高 < 1、極大值進位、第三位小數 ≥ 5（無條件捨去會錯） |
| Q2 | 除數寫成 `0.0`（字串比對 `'0'` 會錯）、被除數是 0（不是 Error）、結果為負、`0.67` 進位 |
| Q3 | `1` 不是質數、`2` 是唯一偶質數、`9` 與 `998001`（`i*i < n` 會漏掉完全平方）、`999983` 測效能 |
| Q4 | 沒有數字（和為 0）、全部是 `0`、單一字元、全數字字串、長字串 |
| Q5 | 長度 5/6/10/11 四個邊界、全數字密碼（`int(input())` 會炸）、含空格（誤用 `split()` 會錯） |
| Q6 | 重根、`a` 為負數（不排序就會反過來）、`c = 0`（有一根是 `0.000`）、無理根、係數含小數 |

```bash
python3 tools/verify_tests.py    # 測資正確性（五道防線）
python3 tools/stress_test.py     # 批改程式扛不扛得住奇怪的學生程式
```

`verify_tests.py` 的五道防線：參考解答全過 → 另一份刻意用不同寫法的獨立實作也全過 →
用 `Fraction`/`Decimal` 純數學重算一次（抓「兩份解答犯同一個錯」）→
24 支故意寫錯一兩行的程式每支都必須至少被一組測資抓到 → 每題 300 筆隨機輸入兩份實作逐字對拍。

`stress_test.py` 灌 21 支惡夢程式：無窮迴圈、無窮 `print`、吃記憶體、無窮遞迴、空檔案、語法錯誤、
BOM / Big5 / UTF-16，以及**竄改 `builtins` 或 `math` 的程式**（每跑完一筆就還原全域狀態，
不會讓某位同學污染排在他後面的所有人）。兩支都接在 `.github/workflows/verify.yml`，每次 push 自動跑。

**還是請三到四位助教各自寫一次作業、跑過測資**：自動驗證擋得住實作 bug，
擋不住「題目本身有兩種合理解讀」。

### 要改東西

| 想做的事 | 怎麼做 |
|---|---|
| 加 / 改測資 | 改 `tools/generate_tests.py` 的 `build_qN()`，再跑一次 generate |
| 改配分或題數 | 同上，改 `BUILDERS` 那個表（每組分數會自動重算） |
| 改參考解答 | 改 `solutions/qN.py`，**一定要重跑** generate（預期輸出是從它產生的） |
| 加一支漏洞程式 | 丟進 `mutants/`，檔名開頭是題號（例 `q5_xxx.py`），驗證時會自動測 |
| 下次作業 HW2 | 複製整個資料夾，改 `BUILDERS` 與 `solutions/`，其餘都能沿用 |

改完務必依序跑：

```bash
python3 tools/generate_tests.py && python3 tools/verify_tests.py && python3 tools/stress_test.py
```

`git push` 之後 GitHub Pages 會自動重新建置（一兩分鐘），網址不變。

## 六、檔案結構

```
index.html                批改網頁（GitHub Pages 入口）
start_local.command       macOS 雙擊即可在本機開網頁（最快，不用網路）
assets/app.js             介面 + 批改流程（檔名辨識、比對、成績表、CSV）
assets/worker.js          Pyodide worker：執行學生程式、餵 input、攔 stdout、逾時砍掉重開
data/tests.js / .json     測資（網頁與命令列共用同一份）
data/solutions.js         參考解答（網頁上可檢視、可自我檢測）
data/mutants.js           故意寫錯的程式（網頁「載入示範」用的資料）
solutions/q1..q6.py       參考解答（只用課內語法）
tools/generate_tests.py   產生測資
tools/verify_tests.py     測資驗證（五道防線，含 mutation testing）
tools/stress_test.py      抗壓測試（21 支惡夢程式 + 污染測試）
tools/grade_cli.py        命令列批改（判定與網頁版一致）
tools/ref_alt/q1..q6.py   第二份獨立實作（對拍用）
mutants/                  24 支故意寫錯的程式
tests/qN/NN.in|.out       純文字測資（釋出給同學 / 手動比對用）
tests/README.md           測資一覽表（每組都寫了在測什麼）
vendor/pyodide/           Pyodide 執行環境（約 12 MB，讓網頁離線可用）
vendor/jszip/             解 zip 用
```

參考解答只使用課內語法：`input()`、`split()`、`format()`、`float()`、`int()`、
多重指定（`a, b, c = input().split()`）、`if/elif/else`、`while`、`for`、`len()`、
字串串接、`** 0.5`。**沒有**用到 list 索引（`data[0]`）、`sorted()`、`map()`、
串列推導式，也沒有 `import math`。
